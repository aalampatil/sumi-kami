# Implementation audit — 2026-11-19

Reviewed the project plan, form/team guide, theme specification, service implementations, builder, respondent renderer, storage adapter, and local setup. Work uses the existing local Clerk development instance and PostgreSQL environment. Production deployment and identity rollout were not changed.

## Fixes and completed implementation

| Finding                                                                                     | Result                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Optional whitespace passed validation but reached typed database columns                    | Storage now shares the answered-state check with validation. A PostgreSQL regression reproduced the numeric insert failure before the fix; the repaired journey preserves zero, false, meaningful spaces, and retry receipts.                     |
| Failed filesystem writes could leave partial private objects                                | The adapter owns its exclusive file handle and removes its newly created object after failure. A test writes real partial bytes, injects an error, checks removal, and successfully retries. Existing objects remain protected against overwrite. |
| Production accepted a relative upload path                                                  | Both supported production environment labels now require an absolute configured directory.                                                                                                                                                        |
| Compound rules were read-only in the builder                                                | A separate recursive condition editor supports AND, OR, NOT, typed comparisons, nested group editing, and the existing complexity limits. The rule's evaluation question is separate from its comparison questions.                               |
| Step routing defaulted to the source step and offered earlier steps                         | Defaults and choices now use only later steps. Source changes preserve valid destinations and replace destinations that are no longer reachable forward.                                                                                          |
| Removing a question could remove an unrelated rule whose literal comparison matched the key | Shared recursive reference inspection checks actual question references, including nested conditions.                                                                                                                                             |
| Sidebar links bypassed the form's unsaved-change warning                                    | A shared hook guards same-origin route links throughout the surrounding shell, as well as ordinary page unloads. Canceling navigation preserves the dirty editor.                                                                                 |
| Custom colors could hide keyboard focus and selected controls                               | The renderer derives a contrasting focus color for both page/control backgrounds. Native choice controls and selected rating borders also retain contrast.                                                                                        |
| The builder could add more than the supported 100 questions to one step                     | The add-question control now respects both per-step and form-wide limits.                                                                                                                                                                         |
| Fresh database examples failed the guarded setup command                                    | Docker Compose and the API example agree on `sumikami_dev`. Existing volume/database behavior is explicitly documented; existing databases were not renamed or reset.                                                                             |
| Current docs described implemented theme delivery as future work                            | Updated theme implementation status, supported limits, and the database diagrams/counts through invitation migration `0013`.                                                                                                                      |

## Remaining work

| Capability                                                  | Current boundary / next implementation                                                                                                                                                                                               |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Production rollout                                          | Provision actual production identity, runtime credentials, origins, infrastructure, and coordinated database/file backups; follow the existing rollout guides.                                                                       |
| Shared attachment storage                                   | The private local filesystem works on one persistent/shared volume. Add an object-store adapter when choosing the production storage architecture.                                                                                   |
| Crash-orphan reconciliation and physical retention deletion | Expired data is already excluded from ordinary response/download access. Add a reviewed maintenance process for reconciling crash leftovers and physically deleting expired rows/bytes. No automatic destructive cleanup is enabled. |
| Distributed rate limiting                                   | Current limits are bounded and local to one API process. Introduce a shared limiter when running multiple API instances.                                                                                                             |
| Email delivery                                              | Invitations currently provide a link to copy/share. The retained notification setting does not deliver response email. A durable delivery mechanism and configured mail transport remain to be integrated.                           |
| Clerk profile synchronization                               | Stable identity mapping is implemented; continuous local display-name/email/profile synchronization still needs a verified event/reconciliation path. Invitation acceptance already checks the current verified Clerk email.         |
| Browser-history draft recovery                              | Link navigation and page unloads warn about unsaved changes. Recovery after client-side Back/Forward navigation still needs implementation.                                                                                          |
| User-managed reusable themes                                | The three local presets, custom colors, fonts, and immutable published snapshots work. A reusable theme library managed by users is a separate future capability.                                                                    |
